# QproFaceTracking V2.1.2

## Before you install

A rooted Quest Pro and the latest [VRCFaceTracking on Steam](https://store.steampowered.com/app/3329480/VRCFaceTracking/) are required. Extract the entire **QproFaceTracking V2.1.2.zip** folder before opening the Hub. GitHub's automatically generated source archives do not contain the ready-to-run app.

Follow the PDF guide included in the ZIP, or use the [text setup instructions](https://github.com/Fwooffy/Qpro-Enhanced-FT-Wireless/blob/main/src/RELEASE_INSTRUCTIONS.md).

## What's in V2.1.2

- **App updates:** The Hub checks for a newer stable GitHub release at startup; automatic checking can be turned off. **Update** downloads and verifies the package, then **Restart and update** replaces the app in its existing folder while preserving local models, recordings, options and connections. Tracking still needs **Start tracking** after reopening.
- **Component updates:** **Components** in the update window checks installed Qpro modules and private Python/PyTorch/ROCm environments against the release's requirements. **Update components** applies needed changes with visible progress and verifies each result. The installed streaming source and ROCm track are preserved. VRCFaceTracking must be closed for module replacement, and Qpro tracking/training must be stopped. Other applications' environments and optional components that were never installed are left alone.
- **Hub layout:** First-time setup now has three required steps, with gaze, AMD acceleration and controller extras separate. Live tracking groups controls under **Eyes**, **Lower-face tracking** and **Hands and controllers**. Advanced settings remain available in expandable sections.
- **Camera preview:** Tracking camera previews default off on a fresh setup. Saved choices are kept, and guided capture windows still open when recording training poses.
- **Cheek session cleanup:** Cheek puff and suck adjustments now apply only while Companion tracking runs. Stop tracking or close the Companion to restore the streaming app's native cheek values. Styles and calibration stay saved for the next session; cheek adjustments can run without starting camera tracking.
- **Experimental developer camera cheeks:** Added an optional v13 cheek head using a new developer recording while preserving every original v8 tongue weight and its visibility gate. Controlled checks on the same wearer showed separate full left/right puffs and a more gradual gentle-left response. Gentle right remains weak and variable; this is not a complete fix or validation across different wearers. The original developer tongue model remains available.
- **Cheek capture guidance:** The pose diagram now labels **YOUR LEFT** and **YOUR RIGHT** from the wearer's perspective, matching the corresponding hand. Longer pose instructions display in full.
- **Headset compatibility:** Added a read-only check for the Quest Pro identity, exact firmware build, tracking engine and current gaze setup. The result distinguishes a recognized engine from live validation and explains the next step. Each feature still runs its own startup checks.
- **Activity feedback:** Setup and tracking failures now keep an explanation and next action above the detailed log. Errors are red, warnings yellow, and normal progress green, with text labels alongside the colors. Added **Copy diagnostics** and **Save log…**. Runtime setup reports progress while it waits; successful process exit alone does not confirm gaze or controller cleanup.
- **Error handling:** Compatibility checks retain both output streams when they fail or time out. Malformed training progress can no longer crash the Hub's output callback. Helper termination and output draining have deadlines; unfinished cleanup remains visible instead of being reported as complete.
- **Keyboard controls:** Improved focus cues, disabled text, Space-key button feedback and screen reader names while retaining the Hub's current style.
- **Tongue response:** Large tongue movements use a faster response while small fluctuations remain smoothed. Avatar updates can follow camera sessions above 24 FPS, with shorter gradual entry and retraction. Gate and direction predictions use one CPU transfer, and diagnostic bars render less often. Visibility protection remains in place; the actual headset-to-avatar improvement still needs live testing. Activity now reports camera and inference rates, processing delay and dropped frames.
- **Tongue output cleanup:** Disabling output is synchronized with prediction publishing, and stale inference results cannot renew the custom tongue override. Stop and expiration continue to restore the native source.
- **Model inference:** Loaded tongue models fold fixed normalization into convolution layers; CPU inference also uses a channels-last layout. The checkpoint files and training architecture stay unchanged. An isolated benchmark with the bundled v8 model pair measured median processing time falling from 24.4 to 19.6 ms on CPU and 13.1 to 11.3 ms on an RX 7900 XTX. These measurements include preprocessing, use synthetic camera inputs and do not measure live VR performance.
- **Stale tongue frames:** Tongue predictions now use the module's 300 ms freshness limit. A rejected late prediction also clears its smoothing and visibility history, preventing that pose from returning on the next fresh frame.
- **Training checkpoint selection:** Validation now scores tongue detail only on frames labeled tongue-visible, matching the training loss. This prevents arbitrary hidden-tongue outputs from favoring a worse visible-pose checkpoint. Direction training requires visible validation examples. Existing model weights are unchanged.
- **VRCFaceTracking module installation:** Qpro installs the selected streaming app's module in its own folder, with a named Qpro card in VRCFaceTracking. Switching or uninstalling removes verified older Qpro copies and keeps recovery files. Separate source modules are preserved and must be removed through VRCFaceTracking before installation.
- **VRCFaceTracking module checks:** Readiness checks use the installer's current module folders and verify the selected source, module card and DLL against this app. Activity explains an older copy, different source, conflicting copy, damaged card or mismatched DLL. **VRCFaceTracking: Running** only identifies the app process, while **Installed · input unchecked** verifies the module files. Confirm moving expressions in VRCFaceTracking's preview before relying on live tracking. A source change made while VRCFaceTracking is running requests a restart.
- **USB connection memory:** The Hub remembers an identity-checked USB Quest Pro and reuses that selection when it opens. Added **Reconnect USB** for a stalled connection while tracking and training are stopped, plus **Forget USB headset** when changing headsets. Reconnection targets the selected USB transport; it does not reset other Android devices or silently choose another headset. USB debugging approval, a working cable and a suitable driver are still required.
- **Uninstall recovery:** Controller removal checks file retirement before unregistering the add-on and restores files on a reported failure. Module removal tries older valid official-module backups when a newer backup is unusable. Incomplete restoration remains visible; setup no longer treats an early successful exit as confirmed removal. Models and recordings are preserved.
- **Windows 10 ROCm:** Added an explicit experimental option for Windows 10 22H2 (build 19045 or later). This does not bypass discrete Radeon selection, GPU training or inference checks. AMD's supported Windows platform remains Windows 11.
- **ROCm 10.1:** Updated the optional AMD recipe to ROCm 10.1.0 and PyTorch 2.14.0, with packages matched to the detected GPU target. Existing verified 10.0 and eligible 7.2.1 environments remain available. Integrated graphics are still excluded; an update is selected only after GPU inference and training checks pass. RX 6000 support remains experimental, and package availability does not guarantee compatibility with every card and driver.
- **Interrupted gaze recovery:** Qpro records the previous headset eye-model selection before applying its temporary patch. A verified interrupted session can be recovered after a reboot, even when its temporary mount is gone. Recovery checks the headset, owning process, original model and temporary source before changing anything; foreign mounts and unknown legacy settings are left alone.
- **Legacy gaze reset:** Added **Reset legacy gaze** for an older session with no recovery record. After explicit confirmation, it chooses the normal nonexperimental headset gaze selection. It refuses active independent-gaze Magisk modules and unverified eye-model or tracking-engine overlays. It does not uninstall modules or overwrite firmware.
- **Gaze setup checks:** **Check gaze setup** now comes before **Prepare gaze**. Its result popup identifies the detected gaze method and gives the next step. Both the popup and setup card explain **Recover Qpro gaze** and **Reset legacy gaze**. Preparation and startup detect conflicting Magisk gaze methods even when experimental-model selection is off. Recovery checks both the ADB and tracking-service views before changing tracking and after restarting it. An enabled Magisk gaze module is not reported as stock tracking.
- **Headset command handling:** Compound root commands now preserve quotes and normalize Windows line endings. This fixes command parsing failures during gaze inspection, session recording and recovery.
- **Stop tracking messages:** The Hub now requires an explicit gaze recovery result instead of treating a successful process exit as proof of restoration. Stopping live tracking restores native cheek values and keeps cheek styles saved for the next session. It does not uninstall the Qpro VRCFaceTracking module or disable a Magisk module; saved eyebrow and smirk adjustments can still apply through the installed Qpro module.
- **Native Virtual Desktop fallback:** Corrected the native face flag used for mouth availability and the alternate tongue layout. Mouth tracking can continue when lower-face data is valid but eye-following expressions are unavailable.
- **Expired live overrides:** Tongue, gaze and pupil overrides release their last custom values when stopped or expired, including when native tracking is unavailable. Inactive modules discard queued packets before becoming active again.
- **Gaze preview cost:** Disabling **Preview tracking cameras** now hides the gaze preview too. Visible gaze previews render at up to 20 FPS while live output retains its sample cadence. Headset tracing and ADB streaming still add processing work.
- **Model selection:** Model and session settings stay locked while tracking runs. Stop tracking, change the selection, then start again to load another model.
- **AMD ROCm setup:** Added checks for the required PyTorch host, device and SDK packages. Missing `torchgen` or incomplete host-package metadata triggers a targeted repair. Python import failures are now reported separately from GPU detection failures.
- **ROCm long-path installation failure:** New installations use a compact per-user Qpro folder instead of the extracted release's nested path. The installer checks its path budget before downloading, and the Hub, tracking and training helpers find the shared environment after it passes GPU checks. Existing environments and recordings are kept. Long-path, download-index and other package failures now have separate messages.
- **AMD GPU selection:** Improved recognition of Radeon driver name variants, including `RX6700XT`. Qpro checks actual HIP device order, excludes integrated graphics and verifies that the selected card matches the installed GPU target. GPU visibility settings inherited from another application are cleared only within Qpro's ROCm process.
- **Cheek calibration rollback:** Restored the earlier three-pose calibration: relaxed, left cheek and right cheek. Removed the four-pose overlap fit and restored its previous Balanced signal mapping and calibrated response. Further calibration changes will wait for live headset testing.
- **Saved cheek profiles:** Earlier three-pose profiles remain usable. Four-pose test profiles are kept on disk but are not applied; Calibrated uses the selected source's bundled developer baseline until a new three-pose calibration is saved. The 1/0, Balanced and native options remain available.
- **Hub shutdown:** Closing the Hub waits for tracking cleanup and recovery of the recorded pre-Qpro eye-model state, then stops the configured PC ADB server. Pending status checks cannot restart it. Other Android tools using that shared server will disconnect.
- **Gaze preparation and engine profiles:** Unsupported engines report the exact firmware build and explain that tracking was left unchanged. Added experimental binary-derived profiles covering the 30 supplied builds, including the exact previously reported V2.4 engine. Preparation and tracking share complete size/hash checks; users do not need to supply an engine file. A detector-call ownership guard rejects stale output on newer layouts without changing gaze angles or smoothing. The additional profiles and new guard still need live headset validation; see the [gaze compatibility test notes](https://github.com/Fwooffy/Qpro-Enhanced-FT-Wireless/blob/main/src/GAZE_ENGINE_TEST_NOTES.md), also included as **Docs/FIX_TEST_NOTES.md** in this test ZIP.
- **Setup guide:** Clarified that an enabled Independent Eye Gaze Magisk module already provides independent gaze: skip **Prepare gaze** and leave the Hub gaze option off. The guide also explains using one gaze method at a time, the temporary headset freeze when applying the Hub's method, and what **Stop tracking** restores. Camera and eye settings use the current Hub labels and locations.

## Updating and testing

For an installed build with the updater, open **Check updates** or **Update available** in the header. Stop tracking, click **Update** to download and verify the package, then **Restart and update** to apply it in the same folder. Models, recordings, enabled options and connection settings are kept. Tracking does not start automatically after the Hub reopens.

Downloads are staged outside the app folder. Replacement keeps a backup for rollback; a retained backup is not removed during temporary-file cleanup. Existing models take priority over a colliding bundled model: the complete existing model pair is kept and the skipped bundled model is reported. If GitHub provides no ZIP checksum or the package does not support the Hub updater, use the manual GitHub download route.

After an app update, open **Components** to review installed module and runtime changes. Updates are applied only when clicked, using the new release's requirements. If updating from an older build without the updater, extract this build into a new folder and preserve the original folder. **Close VRCFaceTracking**, install the matching **Virtual Desktop** or **Steam Link** module from this Hub, then reopen VRCFaceTracking. The restored cheek calibration needs this build's matching module and its Balanced calibration feed.

Use **Recover Qpro gaze** in **First-time setup** to check an interrupted gaze session and restore its verified recorded previous state. If an older build left the experimental eye-model selection enabled without a recovery record, that previous state is unknown. **Reset legacy gaze** lets you explicitly choose the normal nonexperimental selection after confirming the prompt. It refuses active gaze Magisk modules and unverified eye-model or tracking-engine overlays. To return to ordinary headset eye tracking with a gaze Magisk module installed, disable that module and reboot first. Do not combine the Hub's gaze method with an active independent-gaze Magisk module.

To compare ordinary face tracking, stop Qpro tracking, close VRCFaceTracking and wait for its module process to exit. Use **Uninstall Qpro module**, then run exactly one official module for your selected streaming app, installing the official Virtual Desktop or Steam Link module if needed. Hub **Stop tracking** ends live tongue, camera cheek and pupil output and restores native cheek puff and suck values. Cheek styles and calibration stay saved for the next Companion tracking session. Eyebrow settings still apply through the installed module with the Hub closed; turn that switch off for native eyebrows. The module's built-in smirk adjustment remains active until the Qpro module is uninstalled. Neither stopping nor uninstalling the PC module disables a headset Magisk module.

Use **Calibrate cheek puff** on **Live tracking** and complete all three poses when your headset is available. Each streaming app keeps its own profile. Earlier three-pose profiles remain compatible; four-pose test profiles are ignored without deleting them.

Working tongue models from V2.0 onward can be exported through **Model manager** in the old version and imported into this build as a `.qptonguemodel` file. No tongue retraining is required for these fixes. Preserve your original folder and recordings while testing.

## Test status

The latest offline review passed 41 inference/freshness tests and 60 training tests (one existing skip). The paired inference benchmark used 180 predictions per configuration; maximum output differences stayed below `0.000001` on the tested CPU and AMD runtimes. NVIDIA performance and live wearer accuracy were not tested in this pass.

Lip pursing can still expose false cheek values from the native source. Tests against the installed Virtual Desktop module and current source found no lip/cheek index mix-up; **1/0** adjustments can amplify small native cheek values during a Qpro tracking session. **Stop tracking** or closing the Hub now restores native cheek values, including after a Companion crash. Styles and calibration stay saved. The optional v13 camera model gave near-zero puff output on recorded mouth and tongue negatives from the training wearer, including pursed lips; this does not change or validate Meta's native signal. No unverified native purse filter is included.

The v13 candidate was fixed before evaluation. A separate 21-card recording used ambiguous diagram directions for individual puffs, so its left/right labels were not treated as a valid anatomical test or silently changed. Subsequent controlled holds used the wearer's own named side. Full puffs activated the corresponding cheek, but gentle-right strength remained weak and variable. These same-wearer checks do not establish reliable strength calibration, stability, or accuracy on other wearers; the model remains optional and experimental.

Offline updater metadata, package, rollback and UI fixture checks pass. Dialogs were reviewed at normal and minimum sizes; simulated download completion, cancellation and saved Live tracking choices passed. Actual GitHub installation, replacement of an installed release and automatic reopening have not been tested.

This is a test build. Offline cheek, GPU routing, ROCm package repair and compact-path routing, ADB shutdown, gaze preparation, interrupted gaze recovery and production-module override checks pass. USB checks on a working Quest Pro with build `51503870024400340` passed controlled interrupted-session recovery, recovery after a headset reboot and a confirmed legacy selection reset. The controlled recovery used an identical copy of the headset's existing model to test restoration; it did not validate a new gaze model. The headset's original Magisk configuration was restored afterward.

The affected users' convergence behavior, cheek calibration, a fresh ROCm install on the reported RX 7900 XT PC and physical RX 6700 XT testing remain unverified. These fixes do not establish the cause of every user's report. Gaze hooks require an exact reviewed engine identity; newly added profiles still need live validation. AMD ROCm support remains experimental. A listed discrete Radeon, a compatible AMD driver and internet access are needed for a new installation. AMD supports Windows 11; Windows 10 22H2 is available only through **Try ROCm on Windows 10 (experimental)** and still must pass the GPU tests.
