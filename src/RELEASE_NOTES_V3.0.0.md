# Qpro Companion V3.0.0

## Before you install

A rooted Quest Pro and the latest [VRCFaceTracking on Steam](https://store.steampowered.com/app/3329480/VRCFaceTracking/) are required. Extract the entire **QproCompanion.V3.0.0.zip** folder before opening the Hub. GitHub's automatically generated source archives do not contain the ready-to-run app.

**Qpro Companion** is the new public name for QproFaceTracking. The executable, existing app/data folders and `.qptonguemodel` format retain their old names for update compatibility. The legacy **QproFaceTracking.V3.0.0.zip** asset contains the same bytes for older updaters.

Follow the PDF guide included in the ZIP, or use the [text setup instructions](https://github.com/Fwooffy/Qpro-Enhanced-FT-Wireless/blob/main/src/RELEASE_INSTRUCTIONS.md).

## Latest test revision

- **Window repainting:** Actual size changes discard old client pixels, then resizing and restoring finish a complete redraw after the window and its controls have been laid out, including dropdowns and native scrollbars. Repeated text wrapping waits until a resize drag ends, uses a stable content width, and batches related changes. The existing design, controls and scroll positions are preserved. Immediate completed-frame checks cover the reproduced stale scrollbar and black expansion defect; physical corner dragging and smoothness still need confirmation on the affected PC.
- **Tracking health:** Moved the compact camera/output summary to **Activity > Tracking health**, with stale-frame detection. Expand **Show tracking details** for the selected GPU, processing times, result ages and dropped frames. Selecting a GPU alone is no longer treated as proof of live camera input.
- **Optional prerelease updates:** Added a saved **Include prereleases** option, off by default. Published test releases can be checked alongside stable releases. Installation remains click-to-update, with ZIP checksums and package validation. Same-version builds and suffix-tag releases require a manual download.
- **Restricted model loading:** Model checkpoints load as tensors and ordinary metadata. Unsupported Python objects, TorchScript programs and damaged files get readable errors. Existing Qpro exports remain compatible.
- **Setup and cleanup:** ROCm setup isolates external Python/pip settings. Controller failures retain their cleanup evidence, Hub timers and update requests are released on disposal, and module conflicts are checked consistently before camera startup.
- **Developer tongue model:** Added a visibility detector trained with clean-shaven recordings while retaining the original developer tongue direction outputs. In a separate 155-still recording after reseating the same wearer's headset, native fusion reduced missed visible-tongue stills from 75 to 1 with no hidden-tongue false detections. One smile-tip pose was still missed; some older bearded poses worsened and broader wearer/facial-hair tests remain pending. Fresh setups use this model; updates keep personal/imported selections and replace retired bundled choices with the new developer model. Mustachio is the other bundled option. Personal imports/refinements remain usable, and source recordings stay private.
- **Magisk gaze detection:** A bounded, read-only check detects active independent-gaze Magisk modules after connection. Once detected, Hub gaze stays off and disabled, along with **Check gaze setup** and **Prepare gaze**. Pupil, eyebrow and tongue controls work separately. After changing a module, reboot the headset and refresh with **Reconnect USB** or **Check headset compatibility**. A failed scan does not clear a previously detected module; an already-running Qpro gaze session still needs normal Stop cleanup.
- **Clearer failures:** Module installation errors, missing runtime packages, Windows library failures, headset disconnections and package-download failures get separate explanations and next steps. Unexpected camera and pupil exits update the Activity summary. Expected first-install ROCm package probes show a warning while installation continues; final verification failures remain errors.
- **Tongue diagnostics:** Native visibility references must be valid and fresh. Activity distinguishes hidden, visible, disabled and stale output. The new developer detector improves missed detections in the separate same-wearer recording described above; direction outputs are unchanged and live accuracy across other wearers still needs verification.
- **Tongue source layouts:** Corrected the native TongueOut position used by the camera tracker and training preparation for Virtual Desktop's alternate layout. Steam Link retains its standard mapping. New recordings identify their source; ambiguous older labels require the original source to be identified rather than guessed. The Hub rebuilds old prepared data from saved recordings, and working trained models remain usable.
- **Simpler setup and controls:** Three required setup steps, expandable optional settings, and Eyes and Lower-face tracking sections on Facial tracking, plus a separate **Controllers** sidebar page directly below it. Health/backend details are on **Activity > Tracking health**, and the shared Start/Stop bar remains visible. Added small icons and clearer keyboard focus without changing the Hub's visual style.
- **Readable Activity:** Green normal progress, yellow warnings and red errors include text labels. A short explanation and next action appear above the detailed log, with copy and save controls.
- **App and component updates:** Automatic release checks are optional; installation starts only when clicked. App updates preserve models, recordings, options and connections in the existing folder. The Components window can update an installed Qpro module and owned Python/PyTorch/ROCm environments, with progress and result checks. VRCFaceTracking must be closed to update its module.
- **Runtime recovery:** PC runtime updates retain a recovery copy before changing dependencies and restore it after a caught failure. ROCm updates use a separate environment and retain verified fallback environments. A forced process termination can still require recovery from the retained copy.
- **ROCm 10.1:** Added the ROCm 10.1.0 / PyTorch 2.14.0 package recipe. Discrete GPU selection and training/inference checks remain required. RX 6000 support remains experimental. Package and routing checks passed offline; this revision has not had a live ROCm 10.1 installation test.
- **Tongue and pupil processing:** Full-resolution CPU stereo inference shares encoder work between the two views, and pupil thresholds use an equivalent histogram calculation. A local production-worker replay reduced average pair time from 22.73 to 18.93 ms and process CPU time by about 17%, with effectively unchanged predictions. GPU models retain their existing inference path; live PC CPU usage, headset-to-avatar latency and NVIDIA performance still need testing.
- **Training and uninstall checks:** Checkpoint selection now evaluates tongue detail on visible-tongue examples. Module and controller removal retain recovery files and report incomplete restoration explicitly.

These changes have passed offline regression and UI checks. A full installed-app update remains untested. Native cheek values can still activate when lips are pursed, and saved **1/0** adjustments can amplify them during a Companion tracking session. **Stop tracking**, close the Companion or turn **Individual cheek puff (1/0)** off to compare native output; a dedicated filter still needs labeled live samples. See **RELEASE_FIX_NOTES.md** for the detailed changes and validation limits.

## What's in V3.0.0

- **Menu scrolling:** The controller add-on registers its extra inputs before applications load their bindings. Setup prepares Dashboard and VRChat menu scrolling where the installed configuration is recognized, with manual steps in Activity when needed. Ordinary controls and custom choices are kept. Scrolling runs only in **Swipe** during tracking; Stop and other modes leave the extra scroll input neutral. Both thumbs, menu scrolling, ordinary buttons and Stop were checked on the connected Quest Pro; other configurations still need validation.
- **Swipe sensitivity and smoothing:** A **Swipe sensitivity** slider appears only in Swipe mode on **Controllers**. Adjust from 25% to 200% in 25% steps; 100% is the default. Stop tracking, adjust, then start again. Swipe response and Desktop mouse movement smooth changes between sensor updates; live checks found smoother movement and better upward scrolling.
- **Controller updates:** Reinstalling controller components preserves valid saved tuning, mode and controller-side choices, with input disabled after installation. Invalid settings identify their file and key before replacement. Update this add-on separately: close SteamVR, open **First-time setup > Optional hands and controllers**, expand **Show hands setup and uninstall**, then press **Install hand/controller components**, then reopen SteamVR through Virtual Desktop.

- **Interrupted gaze recovery:** Qpro records the previous headset eye-model selection before applying its temporary patch. A verified interrupted session can be recovered after a reboot, even when its temporary mount is gone. Recovery checks the headset, owning process, original model and temporary source before changing anything; foreign mounts and unknown legacy settings are left alone.
- **Legacy gaze reset:** Added **Reset legacy gaze** for an older session with no recovery record. After explicit confirmation, it chooses the normal nonexperimental headset gaze selection. It refuses active independent-gaze Magisk modules and unverified eye-model or tracking-engine overlays. It does not uninstall modules or overwrite firmware.
- **Gaze setup checks:** **Check gaze setup** now comes before **Prepare gaze**. Its result popup identifies the detected gaze method and gives the next step. Both the popup and setup card explain **Recover Qpro gaze** and **Reset legacy gaze**. Preparation and startup detect conflicting Magisk gaze methods even when experimental-model selection is off. Recovery checks both the ADB and tracking-service views before changing tracking and after restarting it. An enabled Magisk gaze module is not reported as stock tracking.
- **Headset command handling:** Compound root commands now preserve quotes and normalize Windows line endings. This fixes command parsing failures during gaze inspection, session recording and recovery.
- **Stop tracking messages:** The Hub now requires an explicit gaze recovery result instead of treating a successful process exit as proof of restoration. Stopping live overrides does not uninstall the Qpro VRCFT module or disable a Magisk module.
- **Native Virtual Desktop fallback:** Corrected the native face flag used for mouth availability and the alternate tongue layout. Mouth tracking can continue when lower-face data is valid but eye-following expressions are unavailable.
- **Expired live overrides:** Tongue, gaze and pupil overrides release their last custom values when stopped or expired, including when native tracking is unavailable. Inactive modules discard queued packets before becoming active again.
- **Gaze preview cost:** Disabling **Preview tracking cameras** now hides the gaze preview too. Visible gaze previews render at up to 20 FPS while live output retains its sample cadence. Headset tracing and ADB streaming still add processing work.
- **Model selection:** Model and session settings stay locked while tracking runs. Stop tracking, change the selection, then start again to load another model.
- **AMD ROCm setup:** Added checks for the required PyTorch host, device and SDK packages. Missing `torchgen` or incomplete host-package metadata triggers a targeted repair. Python import failures are now reported separately from GPU detection failures.
- **ROCm long-path installation failure:** New installations use a compact per-user Qpro folder instead of the extracted release's nested path. The installer checks its path budget before downloading, and the Hub, tracking and training helpers find the shared environment after it passes GPU checks. Existing environments and recordings are kept. Long-path, download-index and other package failures now have separate messages.
- **AMD GPU selection:** Improved recognition of Radeon driver name variants, including `RX6700XT`. Qpro checks actual HIP device order, excludes integrated graphics and verifies that the selected card matches the installed GPU target. GPU visibility settings inherited from another application are cleared only within Qpro's ROCm process.
- **Cheek controls:** Native individual puff/suck use toggleable **1/0** separation. Calibrated/Balanced menus and calibration buttons have been removed from the Hub; existing saved data is kept on disk. Off uses the source's original values.

- **Hub shutdown:** Closing the Hub waits for tracking cleanup and recovery of the recorded pre-Qpro eye-model state, then stops the configured PC ADB server. Pending status checks cannot restart it. Other Android tools using that shared server will disconnect.
- **Gaze preparation and engine profiles:** Unsupported engines report the exact firmware build and explain that tracking was left unchanged. Added experimental binary-derived profiles covering the 30 supplied builds, including the exact previously reported V2.4 engine. Preparation and tracking share complete size/hash checks; users do not need to supply an engine file. A detector-call ownership guard rejects stale output on newer layouts without changing gaze angles or smoothing. The additional profiles and new guard still need live headset validation; see the [gaze compatibility test notes](https://github.com/Fwooffy/Qpro-Enhanced-FT-Wireless/blob/main/src/GAZE_ENGINE_TEST_NOTES.md), also included as **Docs/FIX_TEST_NOTES.md** in this test ZIP.
- **Setup guide:** Updated the PDF and text instructions to explain using one independent gaze method at a time, the temporary headset freeze when applying the Hub's gaze method, and what **Stop tracking** restores.

## Tongue, cheek and pupil updates

- **Facial tracking layout:** Grouped **Tongue model** and tongue output under **Lower-face tracking**, alongside native individual cheek puff/suck switches. Advanced settings expand when needed.
- **Tongue training/refinement:** Quick and Focused training extend the selected tongue model; Full dataset creates a new personal model. Appended cheek camera cards, camera-cheek output and cheek-model training have been removed. Existing imported models remain usable for their tongue outputs.
- **Native individual cheeks:** Puff and suck use toggleable **1/0** separation from the selected streaming app. Off passes through its original values; Stop or closing the Hub restores native cheeks. A deliberate two-sided expression still moves both. No cheek calibration or camera model is required.
- **GPU pupil filtering:** Both eye images can use a verified NVIDIA CUDA or AMD ROCm runtime. Contour fitting, quality checks and smoothing remain on CPU. GPU errors fall back to CPU with an Activity message.
- **Camera workload:** Eye processing uses the latest frame pair and drops superseded work. Unused MJPEG previews are not encoded. Activity includes backend, processing time, frame age and dropped-frame diagnostics.

On the connected RX 7900 XTX, the pupil-only live check maintained approximately 24 FPS with 9–13 ms processing time. A recorded 161-frame comparison matched the CPU pupil results exactly and reduced median processing time from 14.6 ms to 9.9 ms. An earlier three-minute check using tongue, pupils and the since-removed camera-cheek worker maintained a median 23.9 FPS across all five cameras; median pupil processing was 12.7 ms. This is historical evidence from one PC, not a benchmark of the current tongue-only model; NVIDIA and slower-PC performance still need physical testing.

## Updating and testing

Extract this build into a new folder. **Close VRCFaceTracking**, install the matching **Virtual Desktop** or **Steam Link** module from this Hub, then reopen VRCFaceTracking. Use the matching module for this build's native individual cheek switches.

Use **Recover Qpro gaze** in **First-time setup** to check an interrupted gaze session and restore its verified recorded previous state. If an older build left the experimental eye-model selection enabled without a recovery record, that previous state is unknown. **Reset legacy gaze** lets you explicitly choose the normal nonexperimental selection after confirming the prompt. It refuses active gaze Magisk modules and unverified eye-model or tracking-engine overlays. To return to ordinary headset eye tracking with a gaze Magisk module installed, disable that module and reboot first. Do not combine the Hub's gaze method with an active independent-gaze Magisk module.

To compare ordinary face tracking, stop Qpro tracking, close VRCFaceTracking and wait for its module process to exit. Use **Uninstall Qpro module**, then run exactly one official module for your selected streaming app, installing the official Virtual Desktop or Steam Link module if needed. Hub **Stop tracking** ends live tongue and pupil output and restores native cheek puff and suck values. Cheek switch choices stay saved for the next tracking session. Eyebrow settings and the module's built-in smirk adjustment can still apply through the installed Qpro module; turn eyebrow adjustment off for native eyebrows, or uninstall the Qpro module for the original source mappings. Neither stopping nor uninstalling the PC module disables a headset Magisk module.

Working tongue models from V2.0 onward can be exported through **Model manager** in the old version and imported into this build as `.qptonguemodel` files. No tongue retraining is required to keep using their tongue outputs. Preserve your original folder and recordings while testing.

## Test status

This is a test build. Offline cheek, GPU routing, ROCm package repair and compact-path routing, ADB shutdown, gaze preparation, interrupted gaze recovery and production-module override checks pass. USB checks on a working Quest Pro with build `51503870024400340` passed controlled interrupted-session recovery, recovery after a headset reboot and a confirmed legacy selection reset. The controlled recovery used an identical copy of the headset's existing model to test restoration; it did not validate a new gaze model. The headset's original Magisk configuration was restored afterward.

Native individual cheek puff and suck remain dependent on the headset/source signals. The **1/0** adjustment separates a clear leading side but does not train new cheek detections. Compare the two sides in VRCFaceTracking's preview and the avatar; if they differ, inspect the avatar's mappings. The removed camera-cheek model does not affect personal tongue models or their backups.

The affected users' convergence behavior, native cheek response, a fresh ROCm install on the reported RX 7900 XT PC and physical RX 6700 XT testing remain unverified. These fixes do not establish the cause of every user's report. Gaze hooks require an exact reviewed engine identity; newly added profiles still need live validation. AMD ROCm support remains experimental; new installations need a mapped discrete Radeon, a compatible AMD driver and internet access. Windows 11 is the supported path. Windows 10 22H2 users can explicitly enable the experimental option described in the setup guide; its GPU checks must still pass.
